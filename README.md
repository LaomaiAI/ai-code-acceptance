# AI 代码验收报告

粘贴代码,30 秒出逐项验收报告。纯静态页,无登录、无后端、无模型调用。

## 一句话

代码算的和模型判的分开写清:确定性检查由代码本身算出,模型判断单独列出、绝不编造。

## 用法

1. 打开 `index.html`(双击即可,或用任意静态服务器)。
2. 粘贴代码,点"开始验收"(或按 Ctrl/Cmd + Enter)。
3. 看报告:评分、度量、20 项确定性检查(带行号证据)、6 项模型判断(待判定清单)。
4. 导出:复制报告(Markdown)、下载报告(.md);点"复制给 AI 的提示词"可把代码加确定性结果交给任意 AI 模型继续评审模型判断六项。

## 确定性检查(19 项通用 + JSON 专项 1 项,全部本地算出)

| 检查 | 说明 |
|---|---|
| 括号配对 | 圆括号、方括号、花括号是否配对,字符串与注释里的括号不计入 |
| 字符串与注释闭合 | 跨行未闭合的字符串、未闭合的块注释 |
| JSON 格式合法 | 仅识别为 JSON 时运行,做 JSON.parse 校验,报具体错误 |
| 行长度 | 超过 120 字符的行 |
| 行尾空白 | 行尾多余空格或制表符 |
| 缩进一致性 | 制表符与空格缩进混用 |
| 待办标记扫描 | TODO / FIXME / HACK / XXX / BUG |
| 调试代码残留 | console.log、debugger、print、breakpoint 等 |
| 空异常处理 | 吞掉异常的空 catch / except |
| 危险调用 | eval、new Function、innerHTML、document.write |
| 硬编码密钥 | 密码/密钥字面量、sk-、AKIA、GitHub Token 等(证据里不输出密钥明文) |
| 相等比较写法 | JS 的 ==/!=、Python 的 == None |
| 圈复杂度(估算) | 决策点计数,分支过多警告 |
| 函数长度 | 超过 50 行的函数 |
| 重复代码行 | 同一行代码出现 3 次以上 |
| 魔法数字 | 未具名的数字字面量 |
| 注释占比 | 代码超 20 行时注释少于 5% 警告 |
| 文件末尾换行 | 缺少末尾换行符 |
| SQL 字符串拼接 | SQL 语句用 + 拼接变量(注入风险) |
| 文件规模 | 超 1000 行建议拆文件 |

## 模型判断(6 项,本页不判定)

命名是否清晰、逻辑是否正确、有没有结构性重复、性能隐患、可读性与可维护性、是否符合项目约定。需要理解代码意图,静态页不调用模型,只列清单。

## 评分

满分 100,不通过扣 10 分,警告扣 4 分;90 分以上 A,75 分以上 B,60 分以上 C,其余 D。评分只反映确定性检查结果。

## 隐私

无后端、无统计、无上传。代码只在浏览器里运行,关闭页面即消失。

## 局限(已知的,写在页面上)

- 圈复杂度与函数长度为估算(按定义行切分)。
- 模板字符串里的 ${} 代码不参与括号检查。
- 语言识别为启发式,小段代码可能识别为"未知",不影响检查本身。
- 密钥检测是模式匹配,可能漏报非常规写法,也可能误报测试数据中的假密钥,需人工复核。

## 开发

```bash
node test/checker.test.js   # 40 项断言,Node 直跑,无依赖
```

核心逻辑在 `checker.js`(UMD,浏览器与 Node 通用),界面在 `index.html` + `style.css` + `app.js`。

## 部署到 GitHub Pages

仓库建好后(见主代理的部署步骤),把本目录内容推到仓库根目录,在仓库 Settings -> Pages 里选 Deploy from a branch、分支 main、目录 /(root),保存后访问 `https://<用户名>.github.io/ai-code-acceptance/`。
